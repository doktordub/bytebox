# Security Policy

## Supported versions

| Version | Status |
|---|---|
| `main` | Preview support |
| `0.1.x` | Preview support |

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability.

Use one of these channels instead:

1. GitHub private vulnerability reporting, if it is enabled for the repository.
2. Direct maintainer contact through the repository owner before sharing exploit details.

Include:

- affected commit or branch;
- environment details;
- reproduction steps;
- expected impact;
- any suggested mitigation.

## Response goals

- Initial triage: within 5 business days.
- Mitigation or status update: within 10 business days when reproduction is confirmed.
- Public disclosure: after a fix or compensating control is available, unless the maintainer
  approves a different disclosure window.
